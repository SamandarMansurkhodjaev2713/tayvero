# Credential Key Rotation Runbook

## Preconditions

- Backup is verified and restore procedure is current.
- Old key remains available.
- New 32-byte key is generated by an approved secret manager.
- Deployment can be rolled back without removing the old key.

## Procedure

1. Add the new key to the keyring.
2. Deploy with both old and new keys while the old key stays active.
3. Run `bun run security:config-check` in the target environment.
4. Switch the active key ID to the new key and deploy.
5. Confirm new credentials have envelopes referencing the new key.
6. Run the bounded rotation/backfill worker.
7. Monitor failure count, latency and key-ID distribution.
8. Reconcile total credential count against rotated + null + explicitly exempt values.
9. Keep the old key through the rollback and backup-retention window.
10. Remove the old key only after formal approval.

## Abort conditions

- Any authenticated-decryption failure above the expected corrupt-record baseline.
- Reconciliation mismatch.
- Unexpected plaintext writes.
- Missing historical key.
- Increase in integration authorization failures.

## Recovery

Re-enable the prior active key, stop the backfill worker, retain both key versions and investigate using record IDs/correlation IDs only. Never print credential values during recovery.

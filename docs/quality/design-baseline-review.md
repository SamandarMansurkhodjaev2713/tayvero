## Critical review and refinement rounds

1. **Challenge the historical green baseline.** Reran the extracted project on the actual Windows host. The older 571/571 and 15/15 Linux claims did not describe this environment: the initial run had 94 failures. Preserved the distinction between historical release evidence and the current checkout.
2. **Classify failures before altering security behavior.** Traced 21 failures to test fixture directory symlinks requiring Windows privileges. The remaining 73 originated from migration tests using the deliberately POSIX-only encrypted source adapter. Its `O_NOFOLLOW`, ownership, permission, ancestor, symlink and FIFO safeguards remained intact.
3. **Fix only the portable fixture defect.** Used Windows junctions for the two agent test fixtures and retained directory symlinks elsewhere. Reran all 21 affected tests; governance, cancellation, authorization, receipts, replay protection, payload validation and control-field rejection passed. Fixture links are removed only if created by that test.
4. **Critique the evidence parser itself.** Node selected a human-readable reporter on Windows, whereas the gate expected TAP counters. Made the regression runner select TAP explicitly. Added LF/CRLF and multiple-summary coverage so the final summary controls the result. Missing counters are explicit `null`, not a hidden `NaN` or a successful empty run.
5. **Prevent a false green result from omitted coverage.** Hardened the local gate: it requires a positive test count, matching passed count, and zero failures, skips, cancellations and todo tests. Added regression tests for each failure class. The original 73 POSIX cases remain present and visibly failing on this host; no skip-based certification or weakened runtime guard was introduced.
6. **Verify unsupported-platform refusal as behavior.** Added a separate regression confirming invalid roots or missing filesystem capabilities cause `SOURCE_STORE_CONFIG` before storage directories are published. It passed on Windows. This assertion complements the retained POSIX tests; it does not replace their encryption, permissions, concurrency or FIFO acceptance.
7. **Seek genuine Linux execution.** Checked Docker and WSL rather than inventing POSIX evidence. The Docker Linux engine pipe was unavailable. The configured `docker-desktop` WSL distribution failed to start with `HCS/0x800705aa` (insufficient system resources). No Linux tests executed. Real POSIX acceptance remains an external verification requirement.
8. **Recheck database safety and report the block.** Checked only presence of `TEST_DATABASE_URL` and `DATABASE_URL`; both were absent, and no connection secrets were printed. Invoked both external database gates. Their explicit test-database guards blocked execution; no production URL fallback, migrations, reset or provider calls occurred. Bun was not discoverable in these gate processes at this time; later toolchain work must rerun the gates in its prepared environment.
9. **Run the complete existing structural gate.** Executed all 15 stages after the targeted fixes. The 14 non-regression stages passed, including tokens, syntax, manifests, lock metadata, repository audit, credential contract, tenant ratchet and strict governed boundaries. The full result correctly remained FAILED because real POSIX coverage was unavailable on Windows.
10. **Check new tooling against the repository style.** Once the installed Biome binary was available, formatted the three new JavaScript files and corrected its two import-order findings. Biome's final `check --write` completed with exit 0; the four new runtime regressions passed with zero failures/skips after formatting.

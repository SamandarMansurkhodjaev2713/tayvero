# Personal follow-up queue — 2026-10-06

The personal dashboard now puts an actionable queue above sales analytics. It uses the existing authenticated `activities.myTasks({ window: "all", limit: 100 })` contract and the existing `activities.complete` mutation. The team dashboard keeps its existing sales summary and activity panel. No route, API, assignment model, dependency or shared visual system was added.

## Five critical review passes and resulting refinements

1. **Ownership and scope.** `myTasks` filters `createdById`, not an assignee. The heading says **Your follow-ups**, and its provenance says **Tasks you created**. The queue mounts only for `scope=me`. The retained team dashboard panel now also says **Overdue tasks you created**; neither panel claims an assignment workflow.
2. **Calendar boundaries.** “Overdue” means a prior browser calendar day, “Today” includes deadlines earlier today, and “Later” means a subsequent day. The explanation explicitly warns that earlier-today tasks may already be past their scheduled time. Classification compares formatted local calendar dates rather than assuming every day has 24 hours. The server-rendered queue waits for the client clock; the clock updates every minute and on focus/visibility changes. Missing dates remain visible; malformed dates display a review message instead of crashing the formatter or disappearing.
3. **Incomplete snapshots and reachability.** This API has no total or pagination cursor. Every count therefore says **loaded**, with an explicit 100-row maximum and a warning at saturation that later/undated tasks may be missing. The first five tasks in each priority group remain visible; native keyboard-operable disclosure exposes every other loaded task. Later tasks have their own disclosure. Empty copy describes only the loaded snapshot. The old dashboard overdue copy was corrected to avoid claiming all tasks were completed or scheduled.
4. **Failure and completion truth.** Loading, first-load errors, empty success and failed refresh with retained data are distinct states. A stale snapshot retains rows but blocks completion until a successful refresh. The queue can load independently of the analytics query. Mutation errors preserve the task and provide inline recovery copy. Confirmed completion removes only the returned task from this query cache; there is no optimistic “done” claim. The existing activity invalidation refreshes task queries, dashboard and record timelines. Pending completion and active refresh disable duplicate completion actions.
5. **Operating UI and access.** The panel uses existing WorkspacePanel/Notice/Status/Button/Skeleton primitives and inherited appearance tokens. Group headings carry text in addition to status color. Each task has a named completion action and a real workspace detail route for its deal, contact or company; tasks without a linked record say so. Long subjects and names wrap, rows reflow, and disclosure has visible keyboard focus. Status/error announcements are semantic. Tests render the actual component markup for loading, failure, stale rows, record URLs, invalid dates, pending actions and all 100 reachable rows.

# ADR 0010 — Configurable pipeline API boundary

## Context

The configurable pipeline domain and persistence sidecar existed without an authenticated transport consumer. The first Prisma adapter also returned database-shaped rows rather than domain-shaped pipelines and referenced receipt/audit delegates that did not exist in the schema.

## Decision

Expose pipeline management through an authenticated NestJS/tRPC module. The active tenant is derived only from the signed-in session's active organization and is verified through the membership table before any pipeline repository operation. Public DTOs contain no tenant selector.

Pipeline commands use the existing runtime with durable, workspace-scoped command receipts and audit events. Pipeline and stage identifiers are generated by the server on create. Updates use explicit optimistic versions and preserve existing stage identity. The Prisma adapter maps storage records into the validated domain shape and performs collision-free two-phase stage replacement inside the command transaction.

## Consequences

- The API is safe against request-supplied tenant overrides.
- Owners/admins manage pipelines; members receive read-only pipeline configuration and may later use deal transition permissions.
- Retryable mutations require a client-generated idempotency key.
- The legacy `Deal.stage` remains authoritative until a separate dual-write/backfill cutover is verified.
- Live PostgreSQL migration and concurrency verification remain deployment gates.

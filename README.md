## Рабочий день, у которого есть следующий шаг

Клиент уже в базе. Сделка открыта. Дальше начинаются вопросы: кто отвечает, что обещано, где риск и какое действие действительно выполнено.

Tayvero объединяет CRM и управляемые агентные процессы вокруг этих вопросов. Контакты, компании и сделки дают контекст. История и результаты помогают проверить работу. Политики, подтверждения и журнал действий задают границы для AI.

Для команд Узбекистана в проекте есть нормализация местных телефонов при импорте и каталог RU / UZ / EN для операционных экранов. Полная локализация всего продукта ещё в работе.

> **Статус: активная разработка.** Репозиторий содержит реализованные CRM, интерфейсы и механизмы контролируемых действий. Полная эксплуатационная готовность не подтверждена. Текущая модель — отдельное развёртывание для рабочего пространства; совместная база нескольких независимых клиентов не поддерживается как готовый SaaS.

## Что есть в проекте

| Задача команды | Реализация | Что учитывать |
| --- | --- | --- |
| Держать продажи в одном контексте | Контакты, компании, сделки, активности, таблицы и карточки | Авторизованные сценарии требуют проверки в вашем окружении |
| Видеть качество сделки | Детерминированные сигналы здоровья сделки с объяснением | Сигнал помогает разбору; он не гарантирует продажу |
| Управлять работой AI | Определения и версии агентов, запуски, события, результаты и повтор | Внешние провайдеры требуют конфигурации и отдельных проверок |
| Подтверждать значимые действия | Реестр действий, серверные политики, привязка approval к payload, receipts и аудит | Центр подтверждений и продолжение сессий выключены по умолчанию |
| Переносить базу клиентов | CSV / TSV, предпросмотр, mapping, ограниченные batches, receipts и безопасный rollback | Контакты и компании; до 512 KiB / 5 000 строк. XLSX, сделки и связи не реализованы |
| Продолжать импорт в фоне | CLI worker, consent на конкретный job, leases и ограниченные retries | Нужны проверенные PostgreSQL, общий POSIX volume и реально запущенный worker |
| Настроить рабочее пространство | Graphite / Grove / Sand / Indigo, светлая и тёмная темы, плотность таблиц и навигация | Сохранение предпочтений на реальном origin проверяется отдельно |

Подключения Google, Microsoft и Slack представлены в исходном коде. Их доступность зависит от OAuth-настроек, разрешений и состояния провайдера. Telegram, WhatsApp, 1C, единый Inbox и полноценный Outcome Ledger остаются направлением развития.

## Почему управляемый AI

Полезный агент должен уметь объяснить, на каких данных основано решение, какое действие разрешено и чем закончилось выполнение. В Tayvero эти ограничения задаются кодом вокруг модели:

```text
Запрос → проверка контекста → политика → подтверждение при необходимости
       → durable receipt → ограниченный исполнитель → результат → аудит
```

Реестр действий содержит метаданные, а исполнение проходит через прикладной bridge. Подтверждение связано с неизменяемым содержимым действия. Повторы используют receipts и idempotency; неопределённый результат требует разбора вместо слепого повторения. Данные модели не становятся полномочиями пользователя.

Механизмы реализованы в репозитории. Их интеграция с реальными БД, сессиями и провайдерами должна пройти соответствующие release gates.

## Запустить локально

Нужны **Node.js 22+**, **Bun 1.3.12**, **PostgreSQL** и доступ к registry зависимостей. `docker-compose.yml` содержит PostgreSQL 17 для разработки. Для механизмов хранения импортируемых источников требуется Linux / WSL с приватным постоянным POSIX volume.

```sh
git clone https://github.com/SamandarMansurkhodjaev2713/tayvero.git
cd tayvero
```

Создайте `.env` из `.env.example`:

```powershell
# PowerShell
Copy-Item .env.example .env
```

```sh
# Linux / macOS / WSL
cp .env.example .env
```

Перед запуском заполните `BETTER_AUTH_SECRET` собственным случайным секретом, `ALLOWED_SIGN_IN` разрешёнными адресами или доменами и настройте хотя бы один способ входа — Google или Microsoft. Без настроенного провайдера войти в CRM не получится. Для agent bridge задайте одинаковый `AGENT_BRIDGE_SECRET` в приложении и агенте. Не используйте пример keyring как рабочий ключ хранилища.

Сначала сохраните настроенный `.env`, затем установите зависимости: Prisma генерирует клиент во время установки и требует `DATABASE_URL` уже на этом шаге. Для стандартного локального PostgreSQL оставьте URL из примера; замените его, если изменили параметры контейнера.

```sh
bun install --frozen-lockfile
docker compose up -d
bun run db:migrate
bun run db:generate
bun run dev
```

Откройте [localhost:3000](http://localhost:3000). API использует порт `3001`, агент — `2000`. Для необязательных демонстрационных записей выполните `bun run db:seed` на локальной базе; seed также может запрашивать изображения компаний в сети.

`bun run dev` применяет ожидающие миграции локальной БД перед стартом. Проверьте, что `.env` и возможный `.env.local` указывают на локальное окружение. Интеграционные тесты требуют отдельного `TEST_DATABASE_URL`; приложение и тесты не должны использовать одну БД.

Подробности: [настройка окружения](docs/setup.md), [переменные](docs/environment.md), [агент](docs/agent.md).

## Как это устроено

```text
apps/app                 Next.js 16 · React 19 · Tailwind CSS 4
apps/api                 NestJS 11 · tRPC · Bun
apps/agent               Eve · governed action bridge
packages/db              Prisma 7 · PostgreSQL · migrations
packages/ui              Общие компоненты и токены интерфейса
packages/action-registry Контракты и метаданные действий
packages/*-runtime       Pipeline, migration, integration, agent action execution
packages/*-core          Детерминированные правила и политики
tools/quality            Локальные проверки и boundary audits
tools/release            Проверки БД и release gates
```

Bun workspaces и Turborepo связывают приложения и пакеты. Внутренние имена `@crm/*` сохранены, пользовательский бренд — Tayvero. Точные версии и команды находятся в `package.json` и `bun.lock`.

## Проверять, а не предполагать

Минимальная проверка без установленного дерева внешних зависимостей:

```sh
node tools/quality/run-local-tests.mjs
node tools/quality/check-esm.mjs
node scripts/verify-manifests.mjs
node tools/quality/verify-workspace-lock.mjs
node tools/quality/generate-appearance.mjs --check
```

Этот путь проверяет dependency-free suites и структуру. Он не заменяет semantic typecheck, production build, PostgreSQL integration или вход в приложение.

Для полного окружения с отдельной disposable test DB:

```sh
bun run gate:pipeline-postgres
bun run gate:operations-postgres
bun run quality:gate
```

CI подготовлен в [GitHub Actions](.github/workflows/quality-gate.yml). Наличие workflow не означает успешный запуск. Перед эксплуатацией нужны подтверждённые build / types / lint / tests, миграции и concurrency в PostgreSQL, авторизованные E2E, проверки внешних провайдеров и backup / restore.

Новые write / continuation / background flags в `.env.example` выключены. Их включение не заменяет acceptance и запуск worker. Исторический checkpoint и незакрытые обязательства: [MASTER_STATUS](MASTER_STATUS.md), [внешние проверки](MASTER_EXTERNAL_GATES.md), [следующая область работ](MASTER_NEXT_SCOPE.md). Актуальные проверки этого изменения фиксируются в [docs/quality](docs/quality/).
